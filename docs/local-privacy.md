# 本地版联网与隐私策略

本分支默认只允许本机回环地址，不请求 Chatbox 官方服务，不抓取官方数据，不伪造付费许可证。
这是应用层隐私隔离，不是对所有依赖、操作系统及外部程序的“绝对无泄露”认证。

## 已移除/禁用

- 内置 Chatbox AI 商业模型及账号设置入口。
- Sentry Node/React SDK、Google Analytics、Plausible 与 JK 初始化、事件上传和缓存队列。
- Sentry 构建上传插件及其直接依赖；设置中的旧追踪同意不能重新启用采集。
- 自动更新的 SDK、请求、下载、定时任务和自动安装；升级需手动完成。
- 官方 API 探测、备用域名切换、官方链接解析代理、使用次数和分享内容上传。
- 推广弹窗、运营通知；默认本地后端的远程助手目录为空，不影响本地助手。
- 导出聊天 HTML 的官方图片和远程 CDN；导出页带禁止联网的 CSP。
- 旧版域名锁定/混淆跳转代码（原本未启用，也已移除）。
- 启动时自动连接历史 MCP 配置；防止开机启动拥有独立网络栈的扩展子进程。

## 不启动服务器的本地数据闭环

`http://chatbox.localhost` 是虚拟来源，仅由进程内函数返回响应，**不会 DNS 查询、监听端口或打开 socket**。
保留旧接口的只读返回结构，以免界面因接口缺失崩溃：

- 远程配置：来自本地设置，不访问远端。
- 模型目录：来自已保存的提供商模型及随应用打包的默认模型目录。
- RAG 配置：来自用户选择的嵌入/重排模型。
- 更新、通知、运营弹窗、远程助手：无更新、空数据。
- 授权：不可用；云端登录、上传、解析、搜索、商业推理等不支持的操作明确返回错误。

本地助手、会话和模型配置仍在原有本地存储中。新建会话不再强行指定商业模型。
历史配置与聊天记录不删除；旧商业模型或云端知识库需用户自行换成可用的本地模型。

## 配置

在 **设置 → 高级 → 本地网络与数据** 修改并保存：

- **UI 本体的 API Server（不是 AI 模型 API）**：
  - 选择“进程内本地后端”：默认无网络请求，使用下面的本地 JSON。
  - 选择“自建 API Server”：填写如 `http://127.0.0.1:3002` 或 `https://ui-api.example.com:8443`。
    仅支持协议、主机、端口，不填写 `/api`、`/v1`、用户名、密码、查询参数或通配符。
    保存即显式授权该来源，无需在其他端点列表重复添加；不会自动启动服务或探测服务器。
  - 后续远程配置、助手目录、模型目录、RAG 等应用 API 路径拼接到此地址；**不改变 AI 模型提供商地址**。
    后端必须实现兼容的应用 API，普通 OpenAI `/v1` 服务和 Mihomo 控制 API 不可直接代替。
  - 该设置保存在 `localRuntime.appApiServer`。切回本地会移除此字段，不再单独放行旧后端。
    若旧地址同时存在于其他端点放行列表或属于回环地址，仍遵循原有网络权限。
  - 旧官方令牌不发送给自建后端；本版本未提供自建后端账号认证配置，需认证的接口暂不可用。
    商业模型、遥测、推广通知和自动更新不因切换服务器而重新启用。
  - 新请求立即使用新来源；助手及 RAG 缓存按后端区分。保存后重新启动界面可清除其他页面缓存。
    已开始的请求不自动取消；本地 JSON 只在进程内后端模式使用。
- **其他端点源（模型 API 等）**：每行一个完整 HTTP(S) 来源，例如协议、主机与端口；禁止路径、凭据、通配符。
  默认留空，仅允许 `localhost`、IPv4 回环及 IPv6 回环。
  Ollama / LM Studio 使用本机地址无需添加。
  局域网模型地址不是回环，需要明确放行。
  代理连接测试访问首个已放行端点；没有放行端点时测试本机 Ollama 默认端口，不使用 Google 连通性探针。
- **本地 JSON**：支持 `current_version`、`product_ids`、`knowledge_base_models` 等兼容配置。
  可用本地数据填充，不自动“捕捞”官方数据，也不导入授权令牌。
- 配置保存到原来的 Settings 中的 `localRuntime.allowedOrigins` 和 `localRuntime.remoteConfig`；
  桌面版通过原有设置 IPC 持久化，主进程与界面读取同一份设置。

放行远程端点是主动联网，不再属于完全离线。聊天、附件或请求头将按照提供商调用逻辑发送到该端点。
官方/已知遥测域名永久拒绝，即使写入放行列表也无效。
放行按完整来源匹配，不会自动允许子域、其他端口或跳转目标。

## 隔离层及限制

桌面版：启动前安装 fetch、Node HTTP(S)/TCP、外链和代理检查；Electron 的所有 Session 增加
`onBeforeRequest` 检查，覆盖图片、脚本、iframe、Chromium 请求和重定向。
其他运行时还包含 fetch/XHR/WebSocket/EventSource 检查及资源 CSP；它们没有桌面版主进程的完整覆盖，
**不能将本次桌面测试当作 Web/移动原生网络层的隔离证明**。

必须注意：

1. 本机代理、模型服务可以自行转发外网。允许回环并不意味着这些服务已离线。
2. MCP stdio、技能、CLI、Python、浏览器自动化或其他子进程有独立网络栈。
   应用内 JS 拦截不能约束它们；严格离线应禁用这些扩展，或让整个进程树运行在禁外网的网络命名空间/防火墙下。
3. 手动打开的外部浏览器、旧版已构建产物、第三方本地服务不受新源码的全部限制。
4. 放行列表是用户授权来源列表，不是内容级 DLP；若误放行采集端点，其请求可能包含隐私数据。
5. 原有日志/备份仍保存在本地，可能包含敏感内容；不自动上传，但手动分享日志前仍需检查。
6. 本次未联网安装依赖，未启动真实 Electron 抓包，未完成全部依赖的供应链审计。

如需可验证的严格离线，重新构建后，在隔离网络环境里检查启动、设置、聊天、导出、附件及扩展功能的出站流量。

## 验证

`check:local-privacy` 脚本在内存中转译策略，验证：应用后端切换与撤销放行、无效配置回退本地、默认拒绝外网、官方和遥测不可放行、精确来源匹配、
本地接口不调用传输层、上传被拒绝、重定向阻断、真实 Node HTTP/TCP 阻断及回环 HTTP 可用。
Electron Session 使用测试替身，不替代真实 Electron 抓包。
策略单元测试位于 `src/shared/privacy/local-runtime.test.ts`。

锁文件已移除遥测/更新 SDK 的直接依赖入口；历史不可达包快照可能仍存在，后续正常安装时可由包管理器清理。
